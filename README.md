# Isildur

Isildur is the company. **ASE** is its product: an ontology powered data intelligence
platform. This repository is the working prototype: a Python/DuckDB backend that ingests
messy, fragmented source systems and resolves them into one queryable knowledge graph, and
a React frontend that presents it as a landing page, a gated onboarding flow, and an
authenticated app (graph, search, dashboard).

Everything here runs locally. No cloud, no real accounts, no external services. All sample
data is synthetic and generated by the backend itself.

## Repository layout

```
isildur/
  backend/     Python + DuckDB + FastAPI — data pipeline and API
  frontend/    React + Vite + Tailwind — landing site and app
```

See [backend/README.md](backend/README.md) and [frontend/README.md](frontend/README.md) for
each half in detail.

## Architecture, at a glance

The backend is organized around a clear separation between the **domain model**, the
**pipeline** that produces instances of it, and the **API** that serves it:

```
backend/
  ontology.py         domain schema — object types and relationship types (Part B)
  sources.py           provenance manifest for the vendor source systems
  pipeline/            the ETL pipeline, run in order:
    generate_data.py     1. synthesize messy multi-format source systems
    ingest_clean.py       2. ingest + normalize (field mapping, currency, timezone, status vocab)
    entity_resolution.py  3. resolve records into canonical objects + typed links
    findings.py            4. compute operational findings across sources
  api.py               read-only FastAPI surface over the resolved graph
```

The frontend mirrors a conventional separation of routed pages, presentational components,
and shared client logic:

```
frontend/src/
  pages/         one component per route (Landing, RequestAccess, Graph, Search, Dashboard, ...)
  components/    shared and section-level UI, grouped by feature (landing/, access/)
  app/           the authenticated app shell (sidebar, topbar, layout)
  lib/           API client, access/auth context, validation, reference data
```

## Running it locally

**Backend**

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python pipeline/generate_data.py
.venv/bin/python pipeline/ingest_clean.py
.venv/bin/python pipeline/entity_resolution.py
.venv/bin/python pipeline/findings.py
.venv/bin/uvicorn api:app --port 8010
```

**Frontend**

```bash
cd frontend
npm install
npm run dev
```

The frontend expects the API at `http://localhost:8010` (override with `VITE_API_URL`).
